## Короткий ответ

Стейт-менеджер — библиотека для управления глобальным состоянием приложения: хранилище вне компонентов плюс предсказуемый способ его читать и менять. Нужен, когда состояние разделяют много компонентов на разных уровнях дерева и prop drilling / Context уже не справляются. Выбор для React: Redux Toolkit — стандарт для больших команд и сложной бизнес-логики; Zustand — лёгкий и простой для средних проектов; MobX — реактивный, меньше шаблонного кода; Effector — популярен в РФ, хорош для сложных событийных потоков; Jotai/Recoil — атомарный стейт.

## Контекст

Локальный `useState` перестаёт работать, когда одни и те же данные нужны десяткам компонентов (пользователь, корзина, настройки, уведомления). Стейт-менеджер выносит это состояние из дерева компонентов в отдельное хранилище и даёт правила: кто и как его меняет, как подписываться на части стора без лишних ре-рендеров.

## Как строить ответ

### Зачем нужны

- Глобальный доступ к данным без prop drilling.
- Единый источник правды и предсказуемые мутации.
- Инструменты: devtools, тайм-тревел, middleware, персистентность.
- Селекторы: компонент перерисовывается только когда меняется его кусок состояния.

### Основные подходы

- **Flux/Redux**: один стор, чистые редьюсеры, actions; строгая однонаправленность.
- **Реактивный (MobX, Effector)**: observable-состояние, автоматические подписки.
- **Атомарный (Jotai, Recoil, Zustand-слайсы)**: состояние дробится на независимые кусочки.
- **Серверный стейт отдельно**: TanStack Query/SWR часто заменяют половину «глобального стейта».

### Критерии выбора

- Размер команды и проекта: Redux Toolkit — когда нужна дисциплина и единый стиль.
- Порог входа и объём шаблонного кода: Zustand минимален, MobX декларативен.
- Экосистема и devtools: у Redux лучшие.
- Производительность подписок: селекторы/атомы важнее «магии».

## Пример ответа

«Стейт-менеджер — это внешнее хранилище состояния с правилами обновления и подписками. Я бы не тянул Redux в каждый проект: сначала смотрю, нельзя ли обойтись локальным состоянием, Context и TanStack Query для серверных данных. Если глобального клиентского состояния много — для большого продукта возьму Redux Toolkit ради стандартизации и devtools; для среднего — Zustand: минимум кода, селекторы из коробки. MobX подходит команде, привыкшей к ООП и реактивности; Effector — когда сложные цепочки событий и важна производительность.»

## Частые ошибки

- Класть в глобальный стор всё подряд, включая локальный UI-стейт форм.
- Сравнивать библиотеки только по «модности», без критериев выбора.
- Забывать про серверное состояние и кеширование запросов.
- Не знать про селекторы и лишние ре-рендеры.
