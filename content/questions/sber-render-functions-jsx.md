## Короткий ответ

Методы renderHeader/renderBody внутри компонента — это скрытые компоненты без их преимуществ: JSX в них нельзя использовать хуки, легко получить гигантский компонент-«божественный объект», а читабельность и тестируемость падают. Правильнее выносить части в отдельные компоненты Header/Body с явными пропсами.

## Контекст

Вопрос на архитектуру компонентов: где граница между «разбить на функции» и «разбить на компоненты».

## Как строить ответ

### Проблема границ

renderHeader выглядит как компонент, но им не является: нельзя вызвать хук, нет изоляции состояния, React DevTools видит один монолит.

### Производительность и реконсиляция

Локальные функции пересоздаются каждый рендер; если их результат передаётся как element — тип компонента меняется, и React перемонтирует поддерево, теряя состояние и фокус.

### Читаемость

Файл на 500 строк с десятком renderX сложнее ревьюить и тестировать. Отдельный компонент с пропсами — явный контракт.

### Когда допустимо

Мелкая приватная разметка без состояния внутри маленького компонента — вкусовщина. Render props как публичный паттерн — отдельная история, там функция приходит снаружи.

## Пример ответа

Функции renderHeader/renderBody внутри компонента — это псевдокомпоненты: они разбивают разметку визуально, но не дают настоящих границ. Внутри такой функции нельзя использовать хуки, локальное состояние выделить нельзя, и компонент неизбежно разрастается до нечитаемого монолита. Есть и техническая ловушка: если такую функцию определить внутри рендера и использовать как <RenderHeader/>, её тип каждый раз новый — React будет перемонтировать поддерево, теряя состояние и фокус ввода. Поэтому правильный рефакторинг — выделить полноценные компоненты Header и Body с явными пропсами: их можно тестировать, мемоизировать и читать в DevTools. Допустимы render-функции только для мелкой разметки без состояния в маленьком компоненте.

## Частые ошибки

- Вызывать хуки внутри render-функций
- Использовать локальную функцию как JSX-компонент (<RenderX/>) — перемонтирование
- Держать состояние «частей» в родителе вместо выделения компонента
- Путать приватные renderX с паттерном render props
