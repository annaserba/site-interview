## Короткий ответ

React — библиотека UI: JSX, однонаправленный поток данных, экосистема выбирается самостоятельно (роутер, стейт). Angular — полноценный фреймворк: DI, роутер, формы, HTTP, RxJS из коробки, шаблоны с двусторонним биндингом, TypeScript обязателен. React гибче и легче входит, Angular строже и предсказуемее в больших командах.

## Контекст

Классическое сравнение: важны не фанатичные оценки, а инженерные критерии выбора.

## Как строить ответ

### Объём фреймворка

React решает только view: роутинг, формы, стейт — внешние пакеты. Angular — batteries included: всё из коробки, единый «angular way».

### Модель обновления

React: Virtual DOM, ререндер при setState, иммутабельность, односторонний поток. Angular: change detection (Zone.js, всё чаще signals), шаблоны с двусторонним биндингом ngModel.

### Язык и инструменты

Angular жёстко на TypeScript, декораторах, DI и RxJS — выше порог входа, зато единообразие. React — JS/TS по желанию, минимальная церемония.

### Когда что

React: гибкость, большой найм, разнообразные стеки. Angular: энтерпрайз-команды, долгоживущие проекты, жёсткие стандарты из коробки.

## Пример ответа

Принципиальное отличие в объёме: React — библиотека отображения, всё остальное — роутинг, стейт-менеджмент, формы — выбираешь из экосистемы; Angular — полноценный фреймворк с DI, роутером, HTTP-клиентом, формами и RxJS из коробки. Модель данных тоже разная: React — однонаправленный поток, иммутабельный стейт и Virtual DOM с ререндером от setState; Angular — шаблоны с двусторонним биндингом и change detection, исторически на Zone.js, сейчас переезжает на signals. По входу: React проще начать, но решений принимать больше; Angular требует TypeScript, декораторы, RxJS — порог выше, зато вся команда пишет одинаково. Выбирал бы React для гибких продуктовых команд и Angular — для крупных энтерпрайз-проектов, где важнее стандартизация, чем свобода стека.

## Частые ошибки

- Сравнивать «React против Angular» без критериев задачи
- Считать двусторонний биндинг однозначным злом
- Игнорировать стоимость выбора экосистемы в React
- Оценивать по скорости «в hello world», а не в большой команде
