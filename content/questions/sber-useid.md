## Короткий ответ

useId генерирует уникальный стабильный id, одинаковый на сервере и клиенте — нужен для связок label/htmlFor, aria-describedby, aria-labelledby. Константа или Math.random() ломаются: константа одинакова у всех экземпляров компонента, случайное значение различается между SSR-разметкой и гидратацией — получаем hydration mismatch.

## Контекст

Проверяют понимание SSR-гидратации и доступности форм, а не просто знание API.

## Как строить ответ

### Назначение

Связка label и поля: htmlFor + id, aria-атрибуты. Каждому экземпляру компонента — свой id, иначе label кликает не в то поле.

### Почему не константа

const id = 'email' в модуле — одинаковый id у всех экземпляров: дубли в DOM, сломанная доступность и валидация.

### Почему не random

Math.random() в рендере: на сервере одно значение, при гидратации другое — React не сможет сопоставить разметку, предупреждения и перемонтирование.

### Как работает useId

Id детерминированно выводится из позиции компонента в дереве, поэтому совпадает между сервером и клиентом. Ограничение: не для ключей списков — данные меняются, useId статичен.

## Пример ответа

useId возвращает уникальный id, стабильный между серверным рендером и гидратацией — это его главное свойство. Применение — доступность: связать label с полем через htmlFor/id, подсказку через aria-describedby. Почему не константа: модульная константа общая для всех экземпляров компонента — два таких поля на странице получат одинаковый id, и клик по второму label будет фокусировать первое поле. Почему не Math.random(): при SSR на сервере сгенерируется одно значение, а при гидратации в браузере — другое, React увидит расхождение разметки, выдаст hydration mismatch и может перемонтировать поддерево. useId решает это, потому что id вычисляется из положения компонента в дереве. Важно: для ключей списков он не подходит — там нужны id из данных.

## Частые ошибки

- Использовать useId для key в списках
- Генерировать id через Math.random() в рендере при SSR
- Одна модульная константа id на все экземпляры
- Считать, что useId решает уникальность между разными приложениями на странице
