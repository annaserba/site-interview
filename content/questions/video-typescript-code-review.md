## Короткий ответ

На TypeScript code review ищут одни и те же классы ошибок: злоупотребление `any` и `as`-кастами, `// @ts-ignore` без причины, неузкие типы (`string` вместо литерального объединения), отсутствие дженериков там, где типы копируются, игнорирование `null`/`undefined`, неправильная работа с `unknown` и type guards, мутация readonly-структур и рассинхрон типов с реальными данными API.

## Контекст

Формат «вот код, найди проблемы» проверяет не синтаксис, а культуру типизации: умеет ли кандидат держать типы точными и не отключать проверки там, где сложно.

## Как строить ответ

### Что проверять в первую очередь

- `any`, двойные касты `as unknown as T`, `@ts-ignore` — каждый должен быть оправдан.
- Слишком широкие типы: `status: string` вместо `'idle' | 'loading' | 'error'`.
- Дублирование типов вместо дженериков и utility-типов (`Pick`, `Partial`, `ReturnType`).

### Работа с неопределённостью

- Данные сети/JSON — `unknown` + type guard или схема (zod), а не `as User`.
- Опциональные поля: проверки на `undefined` до обращения, optional chaining.
- Различимые объединения (discriminated unions) для состояний вместо кучи boolean-флагов.

### Архитектура типов

- Типы должны следовать за данными: `satisfies`, `as const`, вывод типов из констант.
- Функция не должна возвращать разные формы данных без union-типа.
- Публичный API модуля типизирован явно.

## Пример ответа

«Я иду по коду сверху вниз и отмечаю: все any и as-касты — почти всегда можно переписать через дженерики или type guards; широкие строковые типы — заменить литеральными объединениями; места, где игнорируется null; состояния на нескольких boolean — свернуть в discriminated union. Отдельно смотрю границы: ответы API должны проходить валидацию, а не кастоваться. В конце проверяю, что типы не дублируются и выводятся из источника истины через as const и typeof.»

## Частые ошибки

- Находить только синтаксические мелочи и не видеть системных проблем типизации.
- Предлагать `any` «чтобы быстрее».
- Не знать разницу между `unknown` и `any`.
- Игнорировать runtime-несоответствие типов реальным данным.

## Дополнительные вопросы

- Чем unknown отличается от any?
- Как написать type guard для ответа API?
- Что делает satisfies и чем он лучше аннотации типа?
- Когда оправдан as-каст?
