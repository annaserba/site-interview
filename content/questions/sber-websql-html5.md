## Короткий ответ

Нет. WebSQL Database входил в ранние черновики HTML5, но в 2010 году был исключён из спецификации и помечен deprecated: стандарт фактически зафиксировал SQL-диалект SQLite, что делало независимые реализации невозможными. Замена — IndexedDB. В Chrome WebSQL удалён, живые проекты на него не закладываются.

## Контекст

Вопрос на эрудицию по Web API: проверяют, не путает ли кандидат устаревшие и актуальные механизмы хранения.

## Как строить ответ

### История

WebSQL появился в черновиках HTML5 как реляционная БД в браузере с SQL. Реализовали WebKit и Chrome на базе SQLite.

### Почему исключён

Спецификация описывала диалект SQLite; второй независимой реализации не было и быть не могло — W3C прекратил работу в 2010 году.

### Чем заменили

IndexedDB — NoSQL-хранилище с индексами и транзакциями; поверх него обёртки Dexie, localForage. Для SQL в браузере сегодня — SQLite через WASM.

### Практический вывод

WebSQL не использовать: API удалён из современных Chrome; вопросы миграции с WebSQL → IndexedDB — отдельная тема поддержки legacy.

## Пример ответа

Нет, WebSQL не является частью HTML5 — это распространённое заблуждение, потому что он присутствовал в ранних черновиках спецификации. История такая: WebSQL Database предлагали как реляционную БД в браузере с SQL-синтаксисом, реализации появились в WebKit и Chrome. Но спецификация фактически зафиксировала диалект SQLite: независимая вторая реализация была невозможна, и в 2010 году W3C прекратил работу над стандартом, пометив его как deprecated. Заменой стал IndexedDB — не реляционное, но мощное хранилище с транзакциями и индексами, поверх которого есть удобные обёртки вроде Dexie и localForage. Сегодня WebSQL удалён из Chrome, поэтому в новых проектах его не используют; если нужен именно SQL в браузере, берут SQLite, скомпилированный в WebAssembly.

## Частые ошибки

- Уверенно называть WebSQL частью HTML5
- Путать WebSQL с IndexedDB — это разные API
- Предлагать WebSQL для нового проекта
- Не знать про SQLite WASM как современную альтернативу
