## Короткий ответ

По значению: immutable-вариант — arr.filter(item => item !== value); по индексу: arr.splice(index, 1) — мутирует массив; индекс ищем через indexOf или findIndex для объектов. Delete arr[i] не используем — оставляет дырку (empty slot), длина не меняется.

## Контекст

Простой вопрос на знание мутабельных и иммутабельных методов массивов.

## Как строить ответ

### filter — иммутабельно

Возвращает новый массив без совпадающих элементов. Подходит для React-подхода и удаления всех вхождений.

### splice — мутабельно

splice(index, 1) удаляет на месте и сдвигает хвост. Индекс: indexOf для примитивов, findIndex для объектов по предикату.

### Удаление в цикле

При удалении во время прямого обхода индексы съезжают — идти с конца или собирать новый массив.

### delete — антипаттерн

delete arr[2] оставляет empty slot: length прежний, map пропускает дырку, JSON.stringify даст null.

## Пример ответа

Зависит от того, что есть и нужна ли мутация. Если известно значение — filter: arr.filter(x => x !== value), получаем новый массив, исходный не тронут, заодно удаляются все вхождения. Если известен индекс — splice(index, 1): удалит элемент на месте и сдвинет хвост. Для массива объектов сначала нахожу индекс: const i = arr.findIndex(x => x.id === id), затем splice(i, 1), либо сразу filter(x => x.id !== id). Важно не использовать оператор delete: он оставляет «дырку» — длина массива не меняется, а в позиции остаётся empty slot, что ломает итерации и сериализацию. И при удалении внутри цикла по массиву иду с конца, чтобы индексы не съезжали.

## Частые ошибки

- delete arr[i] вместо splice — дырки в массиве
- splice без проверки, что index !== -1
- Удалять в прямом цикле for по индексам
- Ждать, что filter мутирует исходный массив
