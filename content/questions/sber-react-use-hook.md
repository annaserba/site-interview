## Короткий ответ

use() читает значение ресурса прямо в рендере: промиса (приостанавливает компонент через Suspense до резолва) или контекста. Уникальность: его можно вызывать условно и в циклах, в отличие от остальных хуков. Важное уточнение для интервьюера: use() появился в React 19, а не в React 18.

## Контекст

Каверзный вопрос: формулировка «use() в React 18» — ловушка. Хук представлен в React 19, в 18 была только предварительная поддержка в canary.

## Как строить ответ

### Чтение промисов

const data = use(promise) — компонент приостанавливается, ближайший Suspense показывает фолбэк. Промис должен быть стабильным: создавать в render нельзя — кэшировать или передавать сверху.

### Чтение контекста

use(Context) — аналог useContext, но можно вызывать условно, например читать тему только в ветке if.

### Условный вызов

Единственный хук, который не подчиняется правилу «только верхний уровень»: допустим в if и циклах, потому что React отслеживает ресурс, а не порядок вызова.

### Где применять

Data fetching с Suspense, Server Components, постепенная замена обёрток useEffect+state для простых случаев загрузки.

## Пример ответа

use() — хук из React 19 (в вопросе «React 18» есть неточность: в 18 его не было, только в canary-релизах). Он делает две вещи: читает промис — компонент «засыпает», ближайший Suspense показывает фолбэк, после резолва рендер продолжается; и читает контекст — как useContext, но гибче. Ключевая особенность: use() можно вызывать условно и в циклах, правила хуков на него не распространяются. Типичный сценарий — data fetching: промис создаётся и кэшируется наверху, компонент делает use(promise) и работает с данными синхронно, без useState/useEffect.

## Частые ошибки

- Создавать промис прямо в рендере — бесконечные приостановки
- Не обернуть дерево в Suspense — ошибка вместо фолбэка
- Не знать про Error Boundary для rejected-промиса
- Уверенно отвечать, что use() появился в React 18
