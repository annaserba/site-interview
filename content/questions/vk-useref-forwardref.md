## Короткий ответ

`useRef` возвращает мутабельный объект `{ current }`, который живёт между рендерами и не вызывает ре-рендер при изменении. Два применения: доступ к DOM-элементу (фокус, измерения, интеграция с не-React кодом) и хранение любых значений между рендерами (timer id, предыдущее значение, флаги). `forwardRef` — обёртка компонента, позволяющая родителю передать ref внутрь и прицепить его к нужному DOM-узлу внутри дочернего компонента. В React 19 ref доступен как обычный проп, и forwardRef по сути не нужен.

## Контекст

State в React иммутабелен и его изменение триггерит рендер. Но есть задачи, где рендер не нужен: хранить `setTimeout` id, ссылку на DOM-ноду, предыдущее значение пропа. Для этого и существует ref — «карман» вне реактивного цикла.

## Как строить ответ

### useRef

- `const inputRef = useRef(null); <input ref={inputRef} />; inputRef.current.focus()`.
- Изменение `.current` не вызывает ре-рендер — ключевое отличие от state.
- Типовые кейсы: фокус/скролл, измерение размеров, хранение id таймеров и подписок, prevValue, инстансы сторонних библиотек.
- Не читать/писать `.current` во время рендера — только в эффектах и обработчиках.

### forwardRef

- Родитель не может достучаться до DOM внутри чужого компонента: `<MyInput ref={ref} />` — ref «проваливается».
- `const MyInput = forwardRef((props, ref) => <input ref={ref} {...props} />)`.
- Паттерн `useImperativeHandle` — ограничить «наружу» только нужные методы.
- React 19: `function MyInput({ ref, ...props }) { return <input ref={ref} /> }` — ref обычный проп.

## Пример ответа

«useRef — это мутабельный контейнер, не вызывающий ре-рендер. Использую для DOM-доступа — сфокусировать инпут, померить блок — и для значений вне реактивного цикла: id таймера, предыдущее значение. forwardRef нужен, когда родителю нужен ref на DOM внутри дочернего компонента: оборачиваю компонент и прокидываю ref на конкретный элемент. В React 19 ref стал обычным пропом, так что forwardRef постепенно уходит.»

## Частые ошибки

- Использовать ref там, где нужен state — UI не обновляется.
- Писать в `ref.current` во время рендера.
- Думать, что изменение ref триггерит рендер.
- Прокидывать ref без forwardRef и удивляться, что он не доходит.
