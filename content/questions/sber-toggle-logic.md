## Короткий ответ

Булев стейт с осмысленным именем (isOpen) и функциональное обновление: setIsOpen(prev => !prev) — безопасно при быстрых кликах и батчинге. Рендер — условный: {isOpen && <Modal/>} или тернарник. Не хранить дублирующий стейт, который можно вычислить, и не тогглить через setIsOpen(!isOpen) из замыканий.

## Контекст

Базовый вопрос на работу со стейтом: ловят на setIsOpen(!isOpen) против функциональной формы.

## Как строить ответ

### Функциональное обновление

setIsOpen(prev => !prev) читает актуальное значение из очереди обновлений, а не из замыкания рендера — критично при батчинге и двойных кликах.

### Условный рендер

{isOpen && <Content/>} — монтировать/размонтировать; тернарник для двух веток; CSS-класс hidden — когда нужно сохранить состояние и фокус, но скрыть визуально.

### Производные значения

Не создавать второй стейт «закрыто»: любое значение, вычислимое из стейта, считаем в рендере.

### Удобство

Кастомный хук useToggle или три функции open/close/toggle — когда логика повторяется; важно, чтобы set-функции были стабильны (useCallback при необходимости).

## Пример ответа

Завожу булев стейт с говорящим именем — const [isOpen, setIsOpen] = useState(false). Переключаю только функциональной формой: setIsOpen(prev => !prev). Она берёт актуальное значение из очереди React, поэтому корректна при автоматическом батчинге и быстрых повторных кликах, тогда как setIsOpen(!isOpen) читает устаревшее значение из замыкания текущего рендера. Показ — условный рендер: {isOpen && <Dropdown/>}, либо тернарник, если две ветки. Если нужно скрыть элемент, сохранив его внутреннее состояние — например, черновик формы — использую CSS-сокрытие вместо размонтирования. И не пложу производный стейт: всё, что вычисляется из isOpen, считаю в рендере.

## Частые ошибки

- setIsOpen(!isOpen) — чтение устаревшего стейта из замыкания
- Дублирующий стейт для производного значения
- Размонтирование там, где нужно сохранить состояние элемента
- Имя visible/show вместо is-префикса
