## Короткий ответ

Изолировать стили: CSS Modules или scoped-стили с уникальными хэшами, префиксинг селекторов на уровне сборки, Shadow DOM как радикальный вариант. Токены дизайн-системы версионировать и синхронизировать; глобальные стили — только у shell-приложения. Специфичность держать плоской: один класс, без !important и вложенности, при конфликтах — @layer.

## Контекст

Сеньорский вопрос про изоляцию в микрофронтендах: глобальный CSS не знает границ команд.

## Как строить ответ

### Изоляция селекторов

CSS Modules: уникальные классы с хэшем — конфликт имён исчезает. Альтернативы: префикс приложения (.mf-checkout-*) постфикс-плагинами postcss, CSS-in-JS с изоляцией, Shadow DOM — жёсткая изоляция, но ломает глобальные темы и шрифты.

### Версии дизайн-системы

Общие токены (цвета, отступы) выносить в отдельный пакет и версионировать; миграция по расписанию; shell диктует только каркас и глобальный reset. Две версии одной DS рядом — через префикс классов каждой версии.

### Специфичность

Держать один уровень: .card, не .page .card .title. Запрет на !important и id-селекторы. При пересечении — каскадные слои @layer: у shell ниже приоритет, у микрофронта выше, порядок явный.

### Контроль

Stylelint с запретами, визуальные регрессионные тесты на интеграционном стенде, контрактные проверки токенов в CI.

## Пример ответа

Проблема в том, что CSS глобален: два микрофронта с разными версиями дизайн-системы будут перебивать друг друга. Решаю в три слоя. Первый — изоляция селекторов: CSS Modules дают уникальные классы автоматически, либо префиксим селекторы на сборке; Shadow DOM — радикальный вариант, когда нужна гарантированная изоляция, но он ломает наследование шрифтов и тем. Второй — управление версиями DS: дизайн-токены в отдельном версионируемом пакете, глобальные стили и reset только у shell, две версии DS рядом сосуществуют через разные префиксы. Третий — дисциплина специфичности: плоские селекторы в один класс, запрет !important и id, а для осознанного управления приоритетом — @layer с явным порядком слоёв: слой микрофронта всегда побеждает слой shell независимо от веса селекторов.

## Частые ошибки

- Наращивать специфичность вместо изоляции (гонка селекторов)
- !important как «решение» конфликтов
- Глобальные reset и normalize внутри каждого микрофронта
- Две копии дизайн-системы без префиксов и плана миграции
