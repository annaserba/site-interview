## Короткий ответ

HOC (Higher-Order Component) — функция, которая принимает компонент и возвращает новый компонент с добавленным поведением: `withAuth(Component)`. Render props — паттерн, когда компонент получает функцию в пропе (`render`/`children`) и вызывает её, передавая данные: `<Mouse render={({x, y}) => ...}>`. Оба решают переиспользование логики между компонентами. Сегодня их почти всюду вытеснили кастомные хуки — проще, без wrapper-ада и лучше типизируются; HOC ещё встречается в легаси и библиотеках (React.memo, connect).

## Контекст

До хуков (React 16.8) переиспользовать stateful-логику можно было только через HOC и render props. Понимание паттернов нужно для чтения легаси и библиотек, а сравнение с хуками показывает понимание эволюции React.

## Как строить ответ

### HOC

- Сигнатура: `Component => EnhancedComponent`.
- Кейсы: инъекция данных (connect из Redux), контроль доступа (withAuth), логирование, memo.
- Проблемы: вложенность обёрток (wrapper hell), коллизии имён пропсов, статические методы теряются, ref не пробрасывается без forwardRef.

### Render Props

- Компонент отдаёт данные через функцию-проп; потребитель решает, что рендерить.
- Кейсы: подписки на мышь/размер окна, данные из библиотек (старый Context Consumer).
- Проблемы: глубокая вложенность, неудобная типизация, лишние инлайн-функции.

### Почему хуки победили

- Кастомный хук `useMouse()` — та же переиспользуемая логика без обёрток в дереве.
- Дерево компонентов остаётся плоским, типы выводятся естественно.
- HOC/render props остаются валидными для рендер-ограничений (error boundary — только класс/HOC) и библиотечных API.

## Пример ответа

«HOC — функция-обёртка над компонентом, добавляющая пропсы или поведение: классика — connect и withRouter. Render props — компонент делится данными через функцию в пропе. Оба паттерна из до-хуковой эры: они переиспользовали stateful-логику, но ценой вложенности и проблем с ref и типами. Сейчас ту же задачу решаю кастомным хуком — плоское дерево и простая типизация. HOC оставляю там, где нужно обернуть рендер целиком: error boundaries, memo, библиотечные API.»

## Частые ошибки

- Путать HOC с обычным компонентом-обёрткой (HOC — функция, возвращающая компонент).
- Не знать про проблему ref и static-методов в HOC.
- Считать render props «ант паттерном» — это валидный паттерн, просто вытесненный.
- Не связать паттерны с появлением хуков.
