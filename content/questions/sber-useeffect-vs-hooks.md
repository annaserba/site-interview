## Короткий ответ

useEffect — только для синхронизации с внешними системами: сеть, DOM API, подписки, таймеры. Производные данные — вычисление в рендере или useMemo; ответ на действие пользователя — обработчик события, не эффект; кеширование функций — useCallback; измерение DOM до отрисовки — useLayoutEffect; внешние сторы — useSyncExternalStore. Принцип из документации: «You Might Not Need an Effect».

## Контекст

Проверка ментальной модели: эффекты как «реакция на всё» — антипаттерн React 18+.

## Как строить ответ

### Когда useEffect

Синхронизация с тем, что вне React: fetch с отменой, подписка на socket/resize, document.title, интеграция с не-React виджетами. С cleanup-функцией.

### Когда НЕ useEffect

Производный стейт — считаем в рендере или useMemo. Действие по клику — в обработчике события. «Сделать X при изменении пропа» — ключ по пропу или вычисление, а не эффект.

### Специализированные хуки

useMemo/useCallback — мемоизация вычислений и ссылок; useLayoutEffect — чтение/запись layout до paint; useSyncExternalStore — подписка на внешние хранилища без tearing; useRef — значения без ререндера.

### Признаки лишнего эффекта

Цепочки эффектов, дергающих друг друга; эффект без внешней системы; обновление стейта из пропсов — всё это переписывается без useEffect.

## Пример ответа

Моё правило: useEffect — для синхронизации с внешними по отношению к React системами. Сеть, подписки на сокеты и события window, document.title, таймеры, интеграция с не-React библиотеками — это эффекты, обязательно с cleanup. Всё остальное решается иначе. Производные данные считаю прямо в рендере, тяжёлые — мемоизирую useMemo. Реакция на действие пользователя живёт в обработчике события: «сохранить при клике» — это не эффект. «Сбросить форму при смене userId» — ключ компонента по userId, а не эффект с setState. useLayoutEffect беру только когда нужно измерить DOM до отрисовки, например позиционировать тултип без мигания. Для внешних сторов — useSyncExternalStore, для значений без ререндера — useRef. Если эффект не трогает ничего внешнего — почти наверняка он лишний.

## Частые ошибки

- Цепочки эффектов, синхронизирующие стейт со стейтом
- Сетевой вызов в эффекте там, где есть событие пользователя
- Пропущенная cleanup-функция: утечки подписок и таймеров
- Лишние зависимости «на всякий случай» и бесконечные циклы
